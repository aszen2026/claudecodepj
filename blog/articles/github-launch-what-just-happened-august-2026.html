What Happened

Two notable open source releases landed on GitHub today, August 2, 2026, both from the ecosystem built around Simon Willison's LLM tooling: llm-mcp-client 0.1a0 and datasette-apps 0.2a0. Both shipped as tagged GitHub Releases rather than stable PyPI packages, marking them as early, unstable alpha builds meant for developers who want to kick the tires before wider adoption.

llm-mcp-client extends Willison's llm command-line tool — already popular for querying dozens of model backends (OpenAI, Anthropic, local models via Ollama, and more) from a single interface — with the ability to act as a client for the Model Context Protocol (MCP). In practice, that means llm can now connect to external MCP servers and invoke their tools and resources directly from a terminal session, without custom glue code.

datasette-apps 0.2a0 is the next alpha in Datasette's plugin lineage, aimed at letting developers assemble small interactive "apps" on top of Datasette's SQL-backed data explorer — think lightweight dashboards or retrieval front-ends defined declaratively rather than built from scratch in a web framework.

💡
Both releases use the "a0" alpha tag convention — expect breaking API changes before a 0.x stable or 1.0 release. Neither should be treated as production-ready yet.

Why It Matters

The bigger signal here isn't the version bump — it's what it says about where MCP adoption is heading. Anthropic's Model Context Protocol has mostly been discussed in the context of chat assistants and IDE integrations. Willison building an MCP client directly into llm shows the protocol is now spreading into command-line and scripted workflows, where developers already have strong habits and don't want to rewrite them around a new SDK.

  • For teams already scripting with llm, one CLI can now talk to any supported model and any MCP-compatible tool server, cutting down on one-off integration code.
  • Pairing an LLM tool-calling layer with Datasette's app framework lowers the barrier for building narrow internal tools — natural-language queries over structured data, agentic dashboards — without standing up a full web stack.
  • Because both ship as alpha releases, the developers who adopt early effectively get a say in shaping MCP client conventions before they harden into a de facto standard.

Context

This fits a pattern in Willison's projects: build small, composable, open source tools around whatever protocol or model ecosystem is emerging, rather than betting on one closed platform. The llm tool itself has always leaned on a plugin architecture to add new model backends; extending that same architecture to cover MCP is a natural next step rather than a pivot.

It's also a data point on MCP's trajectory. Since its introduction, the protocol has moved from a novel proposal into command-line tooling in roughly a year and a half — a spread comparable to how OpenAI's function calling or LangChain's tool abstractions caught on, but with one key difference: MCP is a protocol, not a library, so independent client and server implementations can interoperate without sharing a codebase.

On the data-tooling side, datasette-apps continuing its alpha cycle reflects a broader trend of data tools absorbing LLM-era workflows — natural language querying, agentic access to structured datasets — as first-class features rather than bolt-ons.

What To Do Next

  • If you already use llm, install llm-mcp-client 0.1a0 in a throwaway environment and point it at an MCP server you already run — don't wire it into anything you depend on yet.
  • Data teams running Datasette should evaluate datasette-apps 0.2a0 for internal tooling only; alpha versioning means no guarantees around plugin API stability between tags.
  • Watch the GitHub release notes and changelogs for both projects closely — at this stage, version bumps can change plugin APIs without a deprecation window.
  • If you're evaluating MCP for your own stack but don't use llm, this release is still worth reading as a reference implementation for what a minimal, well-behaved MCP client looks like.
💡
Pin exact alpha versions in any test environment (e.g. llm-mcp-client==0.1a0) — alpha tags can be superseded quickly, and reproducing a bug report later gets harder without a pinned version.
